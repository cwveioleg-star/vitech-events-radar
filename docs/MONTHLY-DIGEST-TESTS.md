# Контракт месячного помощника

scripts/monthly_digest.py читает JSON на stdin и возвращает план без сети и создания задач. Пример после явного согласия пользователя, синтетический:

```json
{"platform":"chatgpt","monthly_enabled":true,"capabilities":{"persistent_scheduler":true,"web_search":true},"lookup_succeeded":true,"existing_tasks":[],"timezone":"Europe/Moscow","profile":{"role":"QA","topics":["API"],"formats":["online"],"languages":["ru"]}}
```

Отсутствующее monthly_enabled не означает согласия: для новой задачи operation=consent_required без task/tool_arguments. true допустим только после явного согласия, false — отказ или просьба отключить. Поле не заполняется автоматически из поручения на установку. После согласия и успешной проверки дублей → create с нативными аргументами ChatGPT либо планом фактического scheduler другой среды.

Existing task — нормализованные id/title/prompt/enabled; подтверждение согласия — прочитанный consent_confirmed=true либо маркер `[vitech-events-radar:consent:explicit:v1]` в сохранённом промпте. Активность старой задачи не доказывает согласия. Без него и без нового явного поручения — consent_required, без автоматического изменения или отключения. Маркер подписки `[vitech-events-radar:monthly:v1]` остаётся стабильным для дедупликации. Неоднозначный title без маркера требует сверки.

Для обновления политики v6: refresh_prompt=true, подтверждённое согласие и сохранённые existing_tasks[].profile/timezone. update_prompt содержит ID и prompt; schedule не передаётся, пауза сохраняется. Язык становится ru, прочие предпочтения сохраняются. Resume требует явного resume=true; отсутствие старой задачи не превращает resume в разрешение создать новую. Неизвестные профиль/зона → review_existing, без сброса умолчаний.

Проверяются явное согласие и его отсутствие, legacy-задача, дубли, пауза, ошибка чтения, session-only, отсутствие веба, индивидуальное время, DST/переход года, неизвестный город, публичный профиль, самостоятельный ограниченный поиск с опросом и контактами. Промпт v6 разделяет цену слушателю/спикеру, допускает платные слушателю конференции при бесплатном участии принятого докладчика и фильтрует площадки опроса. Рейтинг Хабра и JSON-аудит необязательны. Для Timepad предусмотрена проверка данных билета. Квоты страниц/полного обхода нет. Фактическую подписку подтверждает только readback после штатной мутации; unit-тесты её не создают.
