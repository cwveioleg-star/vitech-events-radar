# Поддержка скилла

Редактируй правила и источники в skills/vitech-events-radar, обновляй установленный личный скилл штатным способом. Перед записью выполняй [протокол установки и обновления](../skills/vitech-events-radar/references/install-update.md), сохраняя выбранную установку и её идентичность. Публичный профиль компании сверяй с официальным сайтом. Рекомендации персонализируй по роли, стеку и интересам самого сотрудника.

Проверяй личные роли, недоступную память, неизвестный город, бесплатность/русский язык, разные цены слушателю/спикеру и бесплатную заявку без условий спикера, прошедшую дату, закрытую форму, ноль результатов, обычный поиск без квоты, явный расширенный запрос, двухканальный поиск, шестимесячный горизонт CFP и ограниченные выводы, опрос и оба ответа о теме. Не сохраняй реальные профили и журналы в GitHub. Скрипты офлайн, фактические чтения веба они не доказывают.

Месячный маркер v1 стабилен для дедупликации; политика персонального промпта v5. Создание требует явного согласия; старую задачу без подтверждения не менять автоматически. Рейтинг работодателей необязателен. При полном реестре аудит отклоняет уменьшение более чем вдвое; выбранные бренды передавай через selected_brand_ids. Реестр динамический: число записей не фиксировать в проверках, новые имена брать с прочитанной страницы; snapshot — только датированный fallback. При обновлении сохраняй ID, личные настройки и паузу. Различай план и реально сохранённую подписку; тесты не создают задач. При новых API/возможностях платформ сверяйся с их текущей официальной документацией.

Проверки: python3 -m unittest discover -s tests -v; python3 tests/validate_structure.py. Существенные изменения проверяй независимым агентом на сырых синтетических данных с минимальным контекстом и без внешних мутаций. Различай такие прогоны, unit-тесты и реальное веб-исследование. Проверяй блокировки Timepad/Telegram с официальной заменой, изменившийся размер реестра, отсутствие согласия и подтверждённое включение подписки.

Обновляй VERSION, CHANGELOG и TEST-REPORT. Выпускай новый тег и ZIP с одним корнем проекта, внутри которого лежит skills/vitech-events-radar. Не перезаписывай прежний релиз. Сообщение об ошибке должно содержать воспроизводимый запрос без личных данных, факт, первоисточник и время проверки.
