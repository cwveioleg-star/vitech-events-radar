# Личная ежемесячная сводка

## Согласие

Установка или активация скилла не означает согласия на фоновую задачу. После первой подборки один раз предложи: «Включить ежемесячную подборку 1-го числа около 09:00? Агент будет сам выполнять веб-поиск и расходовать доступные лимиты». Укажи личную зону, а при неизвестной — допущение Europe/Moscow.

Создавай задачу только после явного «да» или прямой просьбы включить/создать сводку. Если это уже поручено в текущем контексте, не переспрашивай. Молчание, пропуск, «установи» и ответы на опрос о выступлении согласием не являются. При отказе не предлагай снова в каждом запуске. Отсутствие ответа не мешает разовой подборке.

## Настройка и обновление

1. После согласия подтверди постоянный планировщик и веб-доступ будущего запуска; локальный loop не подходит. Проверь фактическую схему инструмента текущего агента, не выдумывай cron/API.
2. Прочитай все существующие задачи, включая паузы. Ищи `[vitech-events-radar:monthly:v1]` и прежнюю задачу по названию. Ошибка чтения не равна пустому списку; дубли требуют сверки.
3. Новая задача без совпадений — один create штатным инструментом. ChatGPT Work: доступные Automations; другие агенты: подтверждённый постоянный scheduler. Импорт ZIP не выполняет hook. Профиль — только роль, темы, город, формат, без внутренних кейсов.
4. При обновлении сохраняй ID, профиль, расписание, зону и паузу. Политика промпта v4, маркер дедупликации v1 стабилен. Наличие старой активной задачи само по себе не доказывает согласия: без подтверждения не меняй её, не выключай самовольно и не создавай новую; предложи подтвердить управление. Новые промпты содержат `[vitech-events-radar:consent:explicit:v1]`. Это запись ранее полученного согласия, не основание его выдумать.
5. После create/update прочитай сохранённое состояние: ID, активность, правило, зону, ближайший запуск и полный промпт. Только успешный readback подтверждает подписку. Отдельно сообщи результат установки и статус сводки; без согласия — «Скилл установлен; ежемесячная сводка не включена».

`scripts/monthly_digest.py` читает JSON на stdin и выдаёт план, ничего не создаёт. `monthly_enabled=true` передавай только после явного согласия, `false` — после отказа/просьбы отключить; отсутствие поля не даёт согласия. Для существующей задачи учитываются подтверждённый consent_confirmed либо маркер в её прочитанном промпте. Без подтверждения — consent_required без аргументов мутации. platform/capabilities/lookup_succeeded/existing_tasks описывают фактическое состояние. Для обновления политики нужны refresh_prompt=true и сохранённые existing_tasks[].profile/timezone; неизвестные данные сначала восстанови, не подставляй умолчания. Контракт — docs/MONTHLY-DIGEST-TESTS.md репозитория.

## Будущий запуск

Самостоятельный промпт использует обычный режим [поиска](search-strategy.md): агрегаторы и тематические запросы, выбранные организаторы, первоисточники; без обязательных 100 страниц/всех брендов. Реестр проверяется по актуальной странице, файл снимка — только fallback с датой. Timepad/Telegram необязательны. Нужны текущие факты, русский язык, 0 ₽ нужного формата и открытая регистрация. Окно событий — 30 дней, CFP — 6 календарных месяцев. Фильтры качества сохраняются, отрицательный вывод ограничен проверенными источниками.

Верни личную подборку без ожидания интерактивного ответа. В конце дай два вопроса об интересном событии и наличии идеи; ответ обрабатывается в активном чате с немедленным черновиком и Loop/Telegram. При отказе от помощи с выступлением не добавляй опрос/контакты.

Фоновый запуск не меняет расписание, не отправляет сообщения Олегу, не регистрирует человека и не подаёт заявки. Расширенный поиск — только по отдельному согласованному запросу, не при обычном обновлении.

## Управление

Отключение — пауза только этой подписки; возобновление — явный запрос. Изменение времени/тем — та же задача. Не сбрасывай личные настройки. Разработка и тестирование скилла не разрешают создавать или менять живые подписки.
