# Проверка не менее 100 источников за запуск

Порог — 100 **реально прочитанных уникальных релевантных документов** в текущем исследовании. Это страницы календарей, текущих анонсов, форм регистрации/CFP и профильных сообществ; не обязательно 100 доменов. Число источников не заменяет релевантность и проверку карточек.

1. Составь запросы из личной роли/стека, города и русского языка; не используй внутренний контекст компании. Найди календарь/анонсы AvitoTech и Alfa Digital в обязательном порядке. Далее расширяй поиск по реестру sources.md, техническим сообществам и формам CFP.
2. Читай календари и переходи к текущим анонсам и прямым формам. Проверяй конкурирующие даты, год, цену, язык, регистрацию и CFP; предыдущий выпуск используй только для распознавания дубля, не для заполнения квоты.
3. Веди временный журнал только фактически выполненных чтений. Сохраняй инструментальную ссылку на результат и краткую фактологическую заметку. Не выдавай поисковый сниппет за прочитанную страницу.
4. Считай уникальные канонические URL; убирай фрагменты, UTM, сортировку, пагинацию одной ленты и известные зеркала/редиректы. Если одна страница даёт несколько фактов, она всё равно одна. Для зеркал укажи общий source_id, для redirect — конечный canonical_url. Не назначай разные source_id одному документу.
5. Доступ запрещён, timeout, captcha, пустая страница, нерелевантная главная, скопированный сниппет — не засчитываются. Запиши попытку и ищи доступный официальный источник. Не обходи авторизацию.
6. Перед финалом подсчитай журнал: не менее 100 прочитанных источников, отдельно число доменов, присутствие AvitoTech и Alfa Digital. Запусти scripts/research_audit.py, если Python доступен. Только после этого называй охват завершённым. Не сокращай исследование из-за того, что уже нашлось 4 события.
7. При реальном лимите инструментов честно напиши «Неполная проверка: N из 100» и конкретный блокер. Выдай только проверенные карточки, не выдумывай недостающие источники. Не обещай фонового продолжения без реальной задачи.

## Журнал для scripts/research_audit.py

JSON-массив, одна запись на попытку чтения:
```json
[{
  "url": "https://example.org/events/current",
  "canonical_url": "https://example.org/events/current",
  "source_id": "optional-same-document-id",
  "brand": "AvitoTech",
  "kind": "calendar",
  "status": "read",
  "relevant": true,
  "checked_at": "2026-10-15T09:00:00+03:00",
  "tool_ref": "реальная ссылка на результат чтения инструмента",
  "evidence": "Кратко своими словами: какие текущие анонсы или факты прочитаны"
}]
```

kind: calendar/event/registration/cfp/community. status: read/blocked/error. Пример синтетический, не засчитывать его в исследование. Дата чтения — не старше суток, не из будущего. Вызов: `python3 scripts/research_audit.py журнал.json --now ISO8601`. Выход complete=true означает только прохождение структуры и числового порога журнала; агент всё равно отвечает за реальные чтения. Скрипт не ходит в сеть и не хранит журнал.

В выдаче достаточно счётчика и источников рекомендованных карточек; 100 ссылок пользователю навязывать не нужно. Журнал временный, вне каталога скилла и GitHub, без личных данных.
