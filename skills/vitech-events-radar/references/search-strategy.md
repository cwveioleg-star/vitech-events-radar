# Посильный поиск и учёт охвата

## Обычная подборка

1. Определи профиль, текущую дату, 30-дневное окно событий и шестимесячный горизонт CFP. Разбей длинный период на две части для тематических запросов: ближайшие три месяца и следующие три. Пользователь может задать иной период.
2. Используй минимум два разных канала обнаружения: доступный агрегатор/календарь и тематический веб-поиск либо профильное сообщество. Начни с [источников](sources.md); один заблокированный сервис можно заменить. Выполни отдельный поиск CFP по теме и обеим частям периода, включая ранние дедлайны будущих конференций.
3. Выбери несколько подходящих организаторов из актуального рабочего реестра и найденных сообществ. Проверь их официальные анонсы/календарь и CFP. Не обходи всех организаторов и четыре платформы для каждого по умолчанию. Ни у одного бренда нет обязательного или привилегированного статуса.
4. Прочитай первоисточник и регистрацию/форму каждого кандидата. Фильтры — в [quality-rules.md](quality-rules.md). Переходи от агрегатора к организатору; сниппет не доказывает факт.
5. Ориентир — 10–20 прочитанных релевантных страниц, мягкий бюджет — около 25. Это не минимум и не обязанность добрать число. Заверши раньше, если набрана полезная подборка, выполнены два канала обнаружения и поиск CFP по периоду, а все карточки проверены. Если результатов мало, попробуй ещё один профильный маршрут в пределах бюджета и верни меньше вариантов. При реальном лимите инструментов назови, что не удалось проверить.
6. При блокировке Timepad/Telegram используй сайт организатора, другой официальный анонс или доступную форму. Эти платформы необязательны. Если недоступна единственная форма и открытость нельзя подтвердить, исключи карточку; недоступный сервис не равен отсутствию событий. Не обходи авторизацию и не используй личные переписки.

## Расширенный поиск по просьбе

Полный обход рабочего реестра или конкретное число страниц, включая 100, применяй только при явном запросе на такой объём. Сохраняй заданную цель отдельно от обычного режима; не включай расширенный поиск в месячный промпт без отдельного согласия. Даже в полном режиме Timepad/Telegram — дополнительные маршруты, а не обязательная матрица. Если запрос не помещается в ресурсы запуска, выдай проверенную часть и фактическое N из запрошенного числа, без фиктивного завершения.

## Журнал и аудит

Веди краткий временный журнал вне скилла/GitHub, без личных данных: URL, время чтения, инструментальная ссылка и подтверждённые факты. Считай уникальные канонические документы; убирай UTM, фрагменты, пагинацию одной ленты, зеркала и редиректы. Сниппеты, ошибки, captcha, пустые страницы, старые/нерелевантные анонсы не считаются. Поисковый запрос помогает обнаружению, но не считается прочитанной страницей.

При Python используй `scripts/research_audit.py журнал.json --now ISO8601`. Он проверяет предоставленный журнал, не ходит в сеть и не доказывает фактическое чтение. Минимальной квоты по умолчанию нет; поле minimum_reads задаётся только под явный запрос. Короткий синтетический пример структуры:

```json
{
  "mode": "targeted",
  "selected_brand_ids": ["habr-001"],
  "reads": [{"url":"https://example.org/events","brand_ids":["habr-001"],"kind":"calendar","status":"read","relevant":true,"checked_at":"2026-10-15T09:00:00+03:00","tool_ref":"synthetic-read","evidence":"Синтетические данные, не чтение"}],
  "discovery_searches": [
    {"kind":"aggregator","checked_at":"2026-10-15T09:00:00+03:00","tool_ref":"synthetic-1","evidence":"Календарь"},
    {"kind":"web","checked_at":"2026-10-15T09:00:00+03:00","tool_ref":"synthetic-2","evidence":"Тематический поиск"}
  ],
  "brand_checks": [{"brand_id":"habr-001","checked_at":"2026-10-15T09:00:00+03:00","cfp_from":"2026-10-15","cfp_through":"2027-04-15","routes":[
    {"kind":"calendar","status":"read","read_indices":[0],"tool_ref":"synthetic-read","evidence":"Официальный календарь"},
    {"kind":"cfp","status":"not_found","tool_ref":"synthetic-search","evidence":"Поиск текущих выпусков и CFP за весь период"}
  ]}],
  "cfp_search": {"from":"2026-10-15","through":"2027-04-15","community_searches":[{"tool_ref":"synthetic-cfp","evidence":"Темы, обе части периода и независимые сообщества"}],"unresolved":[],"verified_suitable_count":0}
}
```

`mode=full` означает полный обход рабочего реестра по отдельному запросу. Обычный режим требует только объявленные selected_brand_ids. Если бренды не выбирались, явно передай пустой список и опиши охват агрегаторов/сообществ. Основные маршруты — calendar и cfp; timepad/telegram необязательны. Успех аудитора относится только к заявленному плану, а не ко всем событиям рынка.

Текущий список можно передать в `registry`: source_url, checked_at, tool_ref, evidence, brands с уникальными id/name. При чтении актуальной страницы используй её состав, а не жёсткое число 126. Без registry helper использует датированный локальный снимок и сообщает это в результате. Не выдавай fallback за обновлённый список. Дополнительные сообщества — extra_brands с уникальными id/name. Все инструментальные чтения/проверки не старше суток и не из будущего. Старый JSON-массив поддерживается для подсчёта документов, но не подтверждает план поиска.

## Формулировки результата

Назови реальное число прочитанных страниц, каналы/выбранных организаторов и интервал CFP. Не печатай длинный технический журнал. По умолчанию не пиши «N из 100» и не объявляй выборочную подборку полным обзором рынка.

При нуле: «В проверенных источниках за {период} подходящие открытые CFP не найдены». При существенном пробеле добавь его: «Форму организатора X прочитать не удалось». Даже полный обход конечного реестра не доказывает, что возможностей нигде нет. Возможность выбрать проверенное событие для условного вопроса Олегу сохраняется.
