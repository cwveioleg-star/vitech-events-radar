# Охват брендов, 100 источников и горизонт CFP

Это три отдельные проверки: все бренды рабочего реестра, не менее 100 реально прочитанных уникальных релевантных документов и весь горизонт CFP. Сто страниц одного бренда не закрывают общий охват.

## Поиск

1. Открой страницу Хабра из sources.md и рабочий реестр tech-brands.json. Обойди все бренды, добавь обнаруженных организаторов и профильные сообщества. Для каждого проверь календарь/официальные анонсы, Timepad, публичный Telegram и поиск CFP. Не выделяй примеры компаний в обязательную пару.
2. События для посещения по умолчанию — следующие 30 дней. Конференции и открытые CFP — **следующие 6 календарных месяцев**, от сегодняшнего дня до того же числа через шесть месяцев, включая переход года. Если в целевом месяце нет числа, возьми последний день. Ищи будущие выпуски и сроки подачи отдельно: дедлайн может быть скоро, а конференция через пять месяцев.
3. Обход должен охватывать весь интервал, а не только ближайший месяц. Поиск по роли/стеку, секциям, «стать спикером»/CFP и организаторам не прекращается после первых нескольких карточек. Не добавляй в запросы личные или рабочие данные человека.
4. Прочитай текущие календари, анонсы и прямые формы. Подтверди дату/год, язык, 0 ₽ за нужный формат и открытость. Старый выпуск нужен для распознавания дубля, но не для квоты. Учет брендов не означает, что их события автоматически подходят человеку.
5. Веди временный журнал чтений и матрицу маршрутов. Не найденный канал/CFP подкрепи инструментальной ссылкой на поиск и заметкой о запросах/периоде. Если канал найден, его нужно прочитать. Отрицательная выдача по одному запросу не доказывает отсутствие события.
6. При блокировке ищи другой официальный источник. Индекс при 502 не подтверждает актуальное состояние календаря, не закрывает пробел и не считается чтением исходной страницы. Не обходи авторизацию.
7. Проверь аудит перед ответом. Укажи реальное количество страниц и охваченных брендов, интервал CFP и существенные пробелы; 100 ссылок сотруднику не нужны.

## Учёт чтений

Считай уникальные канонические URL. Убирай UTM, фрагменты, сортировку, пагинацию одной ленты, зеркала и редиректы. Один документ с несколькими фактами считается один раз. Общему документу назначай единый source_id, редиректу — конечный canonical_url.

Сниппет, список непрочитанных ссылок, captcha, timeout, пустая страница, нерелевантная главная, повтор и старый анонс квоту не увеличивают. Один список Хабра не равен 126 прочитанным календарям. Источники могут находиться на одном домене.

Журнал хранится временно вне скилла и GitHub, без личных данных. Объект для scripts/research_audit.py:

```json
{
  "reads": [{
    "url": "https://example.org/events",
    "brand_ids": ["habr-001"],
    "kind": "calendar",
    "status": "read",
    "relevant": true,
    "checked_at": "2026-10-15T09:00:00+03:00",
    "tool_ref": "ссылка на фактическое чтение",
    "evidence": "Прочитаны текущие даты, раздел докладов и статус"
  }],
  "extra_brands": [],
  "brand_checks": [{
    "brand_id": "habr-001",
    "checked_at": "2026-10-15T09:00:00+03:00",
    "cfp_from": "2026-10-15",
    "cfp_through": "2027-04-15",
    "routes": [
      {"kind": "calendar", "status": "read", "read_indices": [0], "tool_ref": "ссылка на чтение", "evidence": "Прочитан календарь"},
      {"kind": "timepad", "status": "not_found", "tool_ref": "ссылка на поиск", "evidence": "Проверены название/алиасы и организатор, канал не найден"},
      {"kind": "telegram", "status": "not_found", "tool_ref": "ссылка на поиск", "evidence": "Проверены публичные каналы и официальные ссылки, канал не найден"},
      {"kind": "cfp", "status": "read", "read_indices": [0], "tool_ref": "ссылка на чтение", "evidence": "Проверены будущие выпуски и приём докладов во всём интервале"}
    ]
  }],
  "cfp_search": {
    "from": "2026-10-15",
    "through": "2027-04-15",
    "community_searches": [{"tool_ref": "ссылка на поиск", "evidence": "Запросы по профилю, независимым конференциям и всему интервалу"}],
    "unresolved": [],
    "verified_suitable_count": 0
  }
}
```

Это синтетическая неполная схема, не проведённое исследование. Заполни brand_checks для всех записей реестра; extra_brands принимает новые уникальные id/name. read_indices — индексы reads с нуля; каждый read должен иметь соответствующий brand_ids. Общий официальный документ может подтверждать несколько брендов, но в счётчике остаётся одним.

kind чтения: calendar/event/registration/cfp/community; status: read/blocked/error. Для маршрута status: read/not_found/blocked/snippet_only; последние два оставляют пробел. not_found допускается только после реальных поисков; это не прочитанная страница. Все проверки не старше суток и не из будущего.

Вызов: `python3 scripts/research_audit.py журнал.json --now ISO8601`. Старый JSON-массив допустим для подсчёта чтений, но не подтверждает полный охват. Скрипт сам не читает сеть и проверяет только предоставленные записи.

## Отрицательный вывод о CFP

Фраза **«Пока не вижу открытых конференций, которые тебе подходят как докладчику»** допустима, только если:
- реально проверены все бренды, маршруты и профильные сообщества на весь шестимесячный горизонт;
- прочитано не менее 100 релевантных документов, нет существенных неразрешённых пробелов;
- нет подтверждённых подходящих открытых CFP.

Назови проверенный интервал. Допустимый нижний предел — 4 календарных месяца, только если сотрудник сам сузил горизонт; по умолчанию всегда шесть. Helper по умолчанию требует шесть месяцев; только явно заданное cfp_search.months=4 допускает четыре.

При неполном охвате скажи: «Проверка CFP за {интервал} пока неполная: {конкретный пробел}. В проверенной части подходящий открытый приём не подтверждён». Не делай общего вывода об отсутствии возможностей. При N < 100 дополнительно «неполная проверка: N из 100». Возможность выбрать интересующее событие для вопроса Олегу сохраняется — без обещания открытого приёма.
