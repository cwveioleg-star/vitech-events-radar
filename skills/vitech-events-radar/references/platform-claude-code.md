# Claude Code

Для двух вопросов используй **AskUserQuestion** по фактической схеме инструмента: `questions`, короткий `header`, `options` с `label`/`description`, `multiSelect: false`. Инструмент допускает 2–4 варианта на вопрос; оставь место «Пока не выбираю». Если площадок больше, дай нумерованный список и текстовый ответ номером, сохраняя исходные номера. Без AskUserQuestion (например, headless без интерфейса ответов) используй два текстовых вопроса.

Копируемое обращение покажи в fenced-блоке `text`, под ним Loop/Telegram. В фоне доставь вопросы текстом, без ожидания интерактивного ответа.

Для постоянной месячной сводки после явного согласия проверь **/schedule** (также `/routines`) и доступ к облачным routines, включая GitHub-доступ к выбранному репозиторию с файлами скилла. По текущей документации custom cron задаётся через CLI: согласованное `0 9 1 * *` означает 1-е число в 09:00; проверь личную зону и сохранённое правило. Сначала выполни `/schedule list` и найди прежнюю routine по маркеру, включая паузы; для custom cron используй `/schedule update`; затем сохрани и перечитай ID, расписание, состояние и промпт. Одного плана helper недостаточно. Если /schedule требует аутентификацию или capability отсутствует, подписка не создана — сообщи конкретный блокер.

Облачный запуск получает свежую среду: проверь доставку скилла/полного самостоятельного промпта и веб-доступ. Не подменяй постоянную сводку `/loop` или `CronCreate`: это задачи сессии с ограниченным сроком. Не создавай вместо неё GitHub Actions/системный cron без отдельного поручения.

Проверено 16.10.2026 по официальным источникам: [ввод пользователя](https://platform.claude.com/docs/en/agent-sdk/user-input), [routines и /schedule](https://code.claude.com/docs/en/routines), [планировщики сессии](https://code.claude.com/docs/en/scheduled-tasks). Имена и возможности сверяй с установленной версией.
