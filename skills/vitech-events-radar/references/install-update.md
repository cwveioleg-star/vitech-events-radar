# Установка и безопасное обновление

Применяй этот протокол только при порученной установке или обновлении. Обычная активация скилла не разрешает менять его файлы. Протокол описывает действия агента; он не является автоматическим установщиком и не заменяет ограничения файловой системы.

## 1. Определи среду и одну установку

- Определи агента и версию, ОС, локальный/удалённый режим, поддержку Agent Skills и штатный установщик. IDE и модель сами по себе не определяют способ установки.
- По умолчанию используй личный scope. Проектный — только по просьбе пользователя. Проверь, видит ли выбранный агент этот каталог; не устанавливай копии во все известные roots.
- Сначала найди существующую установку штатным списком скиллов или в подтверждённом каталоге текущего агента. Не обходи весь диск. Общая папка `.agents/skills` может обслуживать несколько агентов: не создавай дубликат и сообщи, какую общую установку обновляешь.
- В управляемой среде сохраняй существующий ID и каталог, даже если он называется `skill-…`. В ChatGPT Work используй доступный Skill Creator и предоставленный им checkout. Этот частный маршрут не применяется к другим агентам.
- Если активную установку нельзя однозначно определить, не угадывай путь. Сообщи конкретную неоднозначность и не меняй файлы до её разрешения.

## 2. Проверь границы до записи

1. Зафиксируй точный абсолютный каталог назначения и его родителя. При обновлении прочитай `SKILL.md` именно в нём и проверь frontmatter `name: vitech-events-radar`. Похожее имя папки недостаточно.
2. Каталог назначения не может быть корнем файловой системы, домашним каталогом, проектом целиком или общим корнем скиллов. Изменения допускаются только в выбранной папке скилла; другие установки и соседние скиллы не затрагивай.
3. Проверь компоненты пути и дерево файлов. Не следуй символическим ссылкам, junction/reparse points и не используй их для записи за пределы папки. При ссылке в затрагиваемом пути останови этот маршрут, не удаляй и не разыменовывай её; выбери подтверждённый штатный способ либо сообщи блокер. Не меняй права доступа для обхода ограничения.
4. Источник — ровно папка `skills/vitech-events-radar/` выбранного релиза. Проверь имя, состав и относительные пути: без абсолютных путей, `..` и ссылок на внешние файлы. При распаковке не допускай выхода из staging-каталога. Подготовь новую версию отдельно от назначения.

## 3. Сохрани текущее состояние

- До изменения существующих файлов создай резервную копию выбранного скилла и проверь её читаемость, список файлов и контрольные суммы. Сохрани копию и локальные настройки вне всех каталогов обнаружения скиллов и вне публичного репозитория. Не копируй другие скиллы; не разыменовывай ссылки. Вне выбранной установки допускаются только эта резервная копия и служебная метаинформация штатного установщика, необходимая для сохранения именно этого скилла; это не разрешает менять другие скиллы или пользовательские файлы.
- Определи предыдущую версию по достоверной записи установщика или проверенному релизу/манифесту. Сравни файлы с ней и новой версией. Совпадение имени не доказывает происхождение файла.
- Составь точные списки добавлений, замен, удалений и сохраняемых локальных файлов. Не считай отсутствие файла в новом релизе разрешением на удаление.

## 4. Примени минимальное обновление

- Заменяй файлы дистрибутива в выбранном каталоге. Локальные изменения сначала сохрани; при конфликте с новой версией не перезаписывай их молча, покажи различия и назови нерешённый конфликт. Неизвестный файл на пути нового ресурса также является конфликтом, а не разрешением на перезапись.
- Удалять можно только обычный файл, который есть в подтверждённом списке предыдущей версии, отсутствует в новой и по контрольной сумме не изменён локально. Если предыдущая версия неизвестна, автоматическое удаление запрещено.
- Неизвестные файлы и изменённые устаревшие файлы сохраняй, даже если их нет в новом релизе. Если они мешают корректной активации, сообщи конфликт, не объявляй обновление завершённым.
- Не удаляй папку установки целиком. Запрещены рекурсивная очистка корня скиллов, маски удаления, `git clean`, `reset --hard` и синхронизация с безусловным удалением неизвестных файлов. Пустые подкаталоги можно оставить.
- Используй штатный updater только после проверки, что его область действия ограничена выбранным скиллом и он не сотрёт локальные/неизвестные файлы. Иначе применяй пофайловый маршрут с теми же границами либо сообщи блокер. Обычное поручение на обновление не разрешает обходить эти ограничения.
- Личные профиль, настройки, ID и паузу ежемесячной задачи не сбрасывай. Правила подписки — в [monthly-digest.md](monthly-digest.md); редактирование дистрибутива не создаёт подписку.

## 5. Проверь результат

Прочитай установленный `SKILL.md` и новые ресурсы, проверь контрольные суммы файлов релиза и относительные ссылки, затем обнаружение скилла самим агентом. В управляемой среде проверь сохранение того же ID. При ошибке восстанавливай только затронутые файлы из проверенной копии, сохраняя неизвестные файлы. Отдельно сообщи итог установки, оставшиеся конфликты и статус ежемесячной сводки. Частичный результат называй частичным.

## Совместимость и официальные источники

Пути в README — примеры для локальных клиентов, проверенные 15.10.2026. Перед установкой сверяй текущую версию и scope по документации выбранного агента. Не переносить локальные пути в облачный аккаунт.

- [Codex / OpenAI](https://developers.openai.com/codex/skills/) — используй текущую документацию и фактически доступный установщик; управляемые облачные скиллы и CLI могут иметь разные механизмы хранения.
- [Claude Code](https://code.claude.com/docs/en/skills) — проверь личный и проектный scope; наличие Claude в названии веб-клиента не означает доступ к локальной папке Claude Code.
- [Cursor Agent](https://cursor.com/docs/skills) — локальные личные roots включают `.cursor/skills` и `.agents/skills`; для Cloud Agents нужны предусмотренные Cursor доставка/синхронизация. Локальная установка не доказывает облачную доступность.
- [GitHub Copilot](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills) — проверь конкретный клиент; локальные личные каталоги и skills репозитория для облачного агента имеют разный scope.
- [Gemini CLI](https://geminicli.com/docs/cli/skills/) — штатный `gemini skills install` поддерживает scope и выбор папки; личный каталог `.gemini/skills` или общий `.agents/skills` проверяй по установленной версии.
- Другие агенты, IDE и ОС: определи реальную поддержку формата по официальной документации или встроенной справке. Если её нет, честно сообщи отсутствие нативной установки. Не создавай вместо неё произвольные конфиги, системные инструкции или глобальные фоновые задания.

Для работы отдельно нужны веб-поиск/чтение сайтов, контекст профиля или ответы пользователя, опрос либо текстовый запасной вариант. Python необязателен. Для месячной сводки дополнительно нужен реальный постоянный планировщик и доступ к вебу в будущем запуске; имя агента этого не гарантирует.
