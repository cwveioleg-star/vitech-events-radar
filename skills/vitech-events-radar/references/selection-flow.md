# Подборка → интерес к выступлению → обращение

После подборки приглашай: **«Если какое-то из этих событий интересно для участия как спикеру, выбери его номер и отметь, есть ли идея темы»**. Рекомендации имеют сквозные номера и стабильные ID; одна конференция не дублируется между посещением и CFP.

Два вопроса в одном коротком опросе:
1. «Какое событие интересно для участия как спикеру?» — проверенные события/конференции из подборки, номер и название, затем «Пока не выбираю».
2. «У тебя уже есть идея темы?» — «Есть идея» / «Пока нет идеи».

У каждого варианта обозначь: **«CFP открыт»** либо **«возможность выступления нужно уточнить»**. Регистрация слушателя не доказывает возможность выступления. События без CFP допустимы для выражения интереса; они не становятся открытыми CFP. Если известно, что приём закрыт, так и напиши. Не показывай несуществующих вариантов. При нуле всех проверенных событий опрос не нужен.

## Нативный выбор и текстовый ответ

В ChatGPT с поддержкой GenUI используй настоящий ask_user_input с двумя single_select, 2–10 вариантов в вопросе, free_text_placeholder. Перед виджетом короткое приглашение; после него закончи ход. Пример формы, а не реальные события:

```json
{"ask_user_input":{"questions":[{"question":"Какое событие интересно для участия как спикеру?","options":["1. event-1 · Проверенный митап · возможность выступления нужно уточнить","2. cfp-1 · Проверенная конференция · CFP открыт","skip · Пока не выбираю"],"type":"single_select","free_text_placeholder":"Можно написать номер события"},{"question":"У тебя уже есть идея темы?","options":["has_idea · Есть идея","no_idea · Пока нет идеи"],"type":"single_select","free_text_placeholder":"Можно сразу написать публичную идею темы"}]}}
```

Сам виджет выводи content reference `genui{...}`. В Claude используй доступный нативный question/choice tool по его текущей схеме. Без UI дай эти же два вопроса текстом: «Ответь, например: 2, идеи пока нет». Не изображай неработающие кнопки.

В фоне доставь подборку с вариантами без ожидания интерактивного ответа. Если продолжение в задаче не поддерживается, предложи ответить в обычном чате. Месячная сводка использует тот же сценарий.

## После ответа

Сохраняй соответствие сквозной номер ↔ ID ↔ проверенная карточка в текущем разговоре. Helper speaker_contact.py принимает точный conference_id, поэтому перед вызовом сопоставь номер с ID. Порядок conferences должен совпадать с показанной подборкой. При устаревших данных перепроверь событие, регистрацию и CFP; новый произвольный URL сначала проверь отдельно.

При одном ответе спроси только недостающее. Название идеи необязательно. Не требуй тему или повторное согласие на черновик. «Пока не выбираю» завершает сценарий без давления; выбор «только посетить» не разрешает черновик о выступлении.

Для подтверждённого открытого CFP — обращение о подготовке к подаче. Для события без подтверждённого CFP — условное обращение: «Мне интересно выступить… Открытый приём пока не подтверждён. Помоги выяснить возможность участия и, если возможно, собрать фактуру». Для закрытого приёма прямо укажи закрытый статус; не обещай, что Олег сможет его открыть.

После двух ответов сразу текст по assets/speaker-message.md, затем Loop и Telegram из references/devrel-contact.md. Без отправки. Пример входа helper: `{"conferences":[проверенные карточки],"selection":{"conference_id":"event-1","topic_state":"no_idea"}}`. --action survey --format json возвращает вопросы; обычный запуск — текст. Нативный writing block/Copy, иначе fenced text block с копированием интерфейса.

Отрицательное заключение о CFP подчиняется search-strategy.md: неполная проверка не разрешает заявить, что подходящих возможностей нет. Это не отменяет приглашение выбрать интересующее проверенное событие.
