# Выбор и обращение

После двух подборок всегда заверши сценарием помощи с выступлением, кроме явного отказа или уже полученных ответов. В опрос входят три статуса из cfp-guidelines.md, включая предварительные площадки с неизвестной ценой/приёмом. У каждого варианта честная пометка статуса. Ноль открытых CFP не отменяет опрос.

Два вопроса:
1. «На какой площадке тебе нужна помощь с выступлением?» — исходные номера/названия площадок и «Пока не выбираю».
2. «У тебя уже есть идея темы?» — «Есть идея» / «Пока нет идеи».

Если площадок нет, первый вопрос замени на «Нужна помощь Олега с поиском площадки?» — «Да, помочь с поиском» / «Пока нет». Второй вопрос сохрани. Не подставляй закрытую, платную спикеру или вымышленную конференцию.

Используй нативный инструмент выбора по фактической схеме платформы; без него два текстовых вопроса с вариантами. В фоне вопросы текстом без ожидания. Перед инструментом покажи обе подборки, чтобы варианты были понятны. Сохраняй номер ↔ ID ↔ карточку, не перенумеровывай после фильтрации.

После ответа спроси только недостающее. Название темы необязательно. Отказ завершает сценарий. Для новой/устаревшей площадки проверь факты. Сразу выдай сам копируемый текст по assets/speaker-message.md и оба контакта из references/devrel-contact.md: подача, уточнение условий или поиск площадки. Никакого дополнительного «подготовить сообщение?». Сообщение отправляет сотрудник.

Помощник speaker_contact.py принимает полные карточки в порядке выдачи. `--action survey --format json` возвращает вопросы; compose — текст и контакты. Выбор по точному conference_id; `help_find` только при отсутствии пригодных карточек, `skip` — отказ. Контракт в candidate-format.md. Нормализуй «доклад про Kafka» до «Kafka». Неизвестное соответствие темы предварительной площадке укажи в обращении; известный конфликт требует адаптации до обращения.
